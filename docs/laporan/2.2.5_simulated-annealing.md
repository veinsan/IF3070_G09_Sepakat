### 2.2.5. Simulated Annealing

*Simulated Annealing* (SA) adalah algoritma *local search* (pencarian yang hanya bergerak dari satu *state* ke *state* tetangganya) yang meniru proses pendinginan logam. Berbeda dengan *Hill-Climbing* yang hanya menerima langkah yang tidak memperburuk, SA sesekali menerima langkah yang memperburuk nilai *objective function*. Peluang penerimaan itu dikendalikan oleh suhu (*temperature*) yang diturunkan setiap iterasi. Pada suhu tinggi, pencarian lebih bebas menjelajah sehingga mampu lolos dari *local optimum* (*state* yang tidak memiliki tetangga lebih baik, tetapi belum tentu terbaik secara keseluruhan). Pada suhu rendah, perilakunya makin menyerupai *Hill-Climbing*. Modul *Simulated Annealing* pada CARGO (*Constraint-Aware Revenue and Geometric Optimization for Vehicle Loading on Cargo Ships*) mengacu pada materi kuliah [4] dan berada di `src/search/simulated_annealing.py`.

Satu iterasi SA terdiri atas langkah berikut.

1. Ambil satu *random neighbor* (tetangga acak) dari *state* saat ini (*current*). Tetangga berupa salah satu dari tiga langkah yang diizinkan spesifikasi: memindahkan kendaraan, menukar dua kendaraan, atau mengubah orientasi.
2. Hitung selisih nilai *objective* ΔE dengan *delta evaluation* (hanya bagian *state* yang berubah yang dihitung ulang).
3. Jika ΔE ≥ 0, langkah selalu diterima. Jika ΔE < 0, langkah diterima dengan peluang e^(ΔE/T).
4. Turunkan suhu: T ← T · α.

Pencarian berjalan tepat N iterasi. Hasil akhir (`final_state`) adalah *state* *feasible* (memenuhi semua *constraint*) terbaik yang pernah dikunjungi selama pencarian, bukan sekadar *state* pada iterasi terakhir.

#### 2.2.5.1. Penerimaan Langkah yang Memperburuk

Peluang penerimaan langkah yang memperburuk dihitung dengan

P(terima) = e^(ΔE/T), untuk ΔE < 0,

dengan:

- ΔE = nilai *objective* tetangga dikurangi nilai *objective* *current*; bernilai negatif jika tetangga lebih buruk;
- T = suhu pada iterasi tersebut (T > 0).

Karena ΔE < 0, eksponennya negatif sehingga peluangnya selalu di antara 0 dan 1. Makin besar penurunan nilai (|ΔE| besar) atau makin rendah suhu, makin kecil peluang langkah tersebut diterima. Untuk ΔE ≥ 0, peluangnya selalu 1 sehingga tidak dicatat dalam plot e^(ΔE/T).

Potongan kode berikut menunjukkan inti perulangan SA, yaitu penerimaan langkah dan penurunan suhu.

```python
for k in range(1, iterations + 1):
    changes = random_neighbor(current, rng)
    d = current.delta(changes)
    evaluations += 1
    improved = False
    if d >= 0:
        accept = True
    else:
        probability = math.exp(d / temperature)
        probabilities.append([k, probability])
        accept = rng.random() < probability
    if accept:
        current.apply(changes)
        if d < 0:
            accepted_worse += 1
        if current.objective > best:
            best = current.objective
            improved = True
    history.append(current.objective)
    incumbent.observe(current)
    feasible_history.append(incumbent.state.objective)
    temperature *= alpha
```

Variabel `incumbent` menyimpan *state* *feasible* terbaik yang pernah dikunjungi. Variabel `probabilities` menyimpan pasangan iterasi dan nilai e^(ΔE/T) yang kemudian digambar sebagai plot.

#### 2.2.5.2. Heuristik Suhu Awal Otomatis

Suhu awal T₀ tidak ditetapkan secara manual karena besar ΔE bergantung pada instans. Pada instans utama, setiap sel yang bertumpuk dikenai penalti 175 (*fee* maksimum ditambah satu). Satu langkah yang menumpuk kendaraan besar dapat menurunkan nilai hingga ribuan, sedangkan *fee* satu kendaraan paling besar 174. Oleh karena itu, T₀ dihitung dari sampel. Sebelum perulangan dimulai, diambil 100 *random neighbor* dari *state* awal. Dari sampel yang memperburuk, T₀ dipilih agar langkah dengan penurunan rata-rata diterima dengan peluang p₀ = 0,8:

e^(mean(ΔE)/T₀) = p₀  ⟹  T₀ = mean(ΔE) / ln(p₀),

dengan:

- mean(ΔE) = rata-rata ΔE dari sampel yang memperburuk (bernilai negatif);
- p₀ = peluang penerimaan yang diinginkan untuk penurunan rata-rata, yaitu `SA_T0_ACCEPT` = 0,8;
- ln(p₀) = logaritma natural p₀ (bernilai negatif karena 0 < p₀ < 1).

Karena pembilang dan penyebut sama-sama negatif, T₀ selalu positif. Jika tidak ada sampel yang memperburuk, T₀ = 1. Heuristik ini merupakan keputusan implementasi CARGO sendiri. Heuristik ini tidak menjamin bahwa setiap langkah buruk diterima dengan peluang 0,8, karena nilai 0,8 hanya berlaku untuk penurunan sebesar rata-rata sampel.

```python
def initial_temperature(
    state: State, rng: random.Random, samples: int = SA_T0_SAMPLES, accept_prob: float = SA_T0_ACCEPT
) -> float:
    ...
    worse = []
    for _ in range(samples):
        d = state.delta(random_neighbor(state, rng))
        if d < 0:
            worse.append(d)
    if not worse:
        return 1.0
    return (sum(worse) / len(worse)) / math.log(accept_prob)
```

#### 2.2.5.3. Perhitungan Laju Pendinginan

CARGO memakai *geometric cooling* (pendinginan geometris), yaitu suhu dikalikan konstanta α setiap iterasi sehingga Tₖ = T₀ · α^k. Karena T₀ berbeda pada setiap *seed* (bilangan awal pembangkit acak), nilai α yang tetap akan membuat suhu akhir tiap *run* berbeda. Oleh karena itu, α dihitung agar suhu turun tepat dari T₀ ke T_min dalam N iterasi:

T₀ · α^N = T_min  ⟹  α = (T_min / T₀)^(1/N),

dengan:

- T_min = suhu akhir, yaitu `SA_T_MIN` = 0,01;
- N = banyak iterasi, yaitu `SA_ITERATIONS` = 100.000;
- k = nomor iterasi.

Jika T₀ ≤ T_min, α ditetapkan 1 agar suhu tidak naik. Dengan cara ini, semua *run* memiliki jumlah iterasi yang sama dan suhu akhir yang sama sehingga lebih adil untuk dibandingkan.

```python
def cooling_rate(t0: float, t_min: float, iterations: int) -> float:
    ...
    if t0 <= t_min:
        return 1.0
    return (t_min / t0) ** (1 / iterations)
```

#### 2.2.5.4. Definisi *Stuck* di *Local Optimum*

Spesifikasi meminta frekuensi *stuck* (terjebak) di *local optimum*. CARGO mendefinisikan *stuck* secara ketat: *current* benar-benar tidak memiliki tetangga yang lebih baik. Pemeriksaan dilakukan pada *checkpoint* (titik periksa) setiap `SA_STUCK_WINDOW` = 500 iterasi dengan langkah berikut.

1. Seluruh tetangga *current* diperiksa satu per satu sampai ditemukan tetangga dengan ΔE > 0 atau semua tetangga habis diperiksa.
2. Jika tidak ada tetangga yang lebih baik, *checkpoint* tersebut dicatat sebagai *local optimum*.
3. Satu episode *stuck* adalah rangkaian *checkpoint* *local optimum* yang berurutan. Episode hanya dihitung pada *checkpoint* pertamanya dan berakhir ketika ada *checkpoint* yang menemukan tetangga lebih baik.

```python
if k % stuck_window == 0:
    local_optimum = True
    for neighbor in all_neighbors(current):
        delta = current.delta(neighbor)
        evaluations += 1
        confirmation_evaluations += 1
        if delta > 0:
            local_optimum = False
            break
    local_optimum_checks.append([k, local_optimum])
    if local_optimum and not in_stuck_episode:
        stuck_iterations.append(k)
    in_stuck_episode = local_optimum
```

Definisi ini dipilih agar angka *stuck* benar-benar menunjukkan *local optimum*, bukan sekadar tidak ada perbaikan. CARGO juga mencatat *stagnation* (stagnasi), yaitu jumlah jendela 500 iterasi tanpa nilai terbaik baru, sebagai besaran terpisah. Dua hal perlu dicatat dari definisi ini.

- Pemeriksaan hanya dilakukan secara berkala sehingga *local optimum* yang dikunjungi sebentar di antara dua *checkpoint* tidak terdeteksi.
- Pemeriksaan tidak memakai pembangkit acak dan tidak mengubah *current* sehingga lintasan SA tidak berubah. Namun, evaluasinya tetap dihitung dalam jumlah evaluasi dan durasi pencarian.
